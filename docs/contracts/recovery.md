# Publication and recovery contract

This is the single failure/recovery table required by D0. ADRs 0009–0013 and 0015 govern it. Each row is a future fault-injection test, not a current implementation claim. Recovery never invents signatures, deletes user edits, or overwrites externally advanced refs.

An operation progresses through durable journal → fully prepared signed bytes → external effects/member objects → published receipt → records ref → SQLite. An operation-specific order may create retention refs before the proposal branch. The receipt is the accepted-state boundary; external effects may exist earlier and must be reported as pending. Publication must not declare success before its required effects exist. Completing cleanup is not required for a durable close to remain closed.

| Boundary / side effect | Interruption or conflict | Required recovery / retry | Owner / test |
|---|---|---|---|
| Root key creation outside repo | Crash during temp write/rename; another init wins | Private directory/file modes; atomic no-clobber creation; preserve existing key; never create a replacement identity silently | M0.4/M0.11 `RootKeyCreationRecovery` |
| `.git/info/exclude` and init metadata | Repeated/partial init; linked worktree | Idempotently ensure Ledger exclusion in the host repo; preserve other entries/config; case policy and root public identity stay consistent | M0.11 `InitInterrupted` |
| OS RecordStore / daemon / worktree locks | Owner dies, simultaneous startup or reversed lock acquisition | OS releases dead-owner lock; one daemon/fork owner; documented consistent lock ordering; no PID-only stale-lock guess | M0.6/M1.2/M1.4 `LockOwnerDeath` |
| Local operation journal | Crash before durable journal or while preparing | No unjournaled external effect; retain interrupted status if bytes/authority incomplete; keep journal across reindex; exclude it from export | M0.6/M0.8 `JournalPrepare` |
| Object temporary file, fsync, rename, directory fsync | Crash before/after each; truncated/hash-mismatched final object | Ignore incomplete temp; preserve valid content; quarantine/report corrupt final file; member alone remains pending | M0.6/M0.8 `ObjectPublication` |
| Receipt prepare/publication | Crash before/after receipt durability; missing member/dependency | Prepared bytes alone are pending; complete published group accepted once; incomplete group unavailable/pending; never regenerate a receipt with a lost key | M0.6/M0.8 `ReceiptPublication` |
| Retry / incompatible receipt | Same id same request; same id different request or imported incompatible receipt | Return original frozen result; reject mismatched input; preserve imported conflict and block dependent mutations | M0.6/M0.7 `OperationIdentity` |
| Records-ref CAS | External tip advances between read/update; retry limit | Union disk/ref records; two distinct old/actual parents; bounded retry; preserve semantic forks; never force overwrite | M0.7 `ExternalRecordsRefAdvance` |
| Disk/ref reconciliation | Object only on disk or only in ref, including receipts | Add/materialize valid bytes; preserve pending visibility until complete receipt; report missing dependencies and corruption | M0.8 `RecordCopiesRecovery` |
| SQLite transaction/index publication | Crash after receipt/ref but before/during index; database deleted | Replay committed groups deterministically; no duplicate logical outcomes; conflicts and durable results identical | M0.9 `IndexPublication` |
| Lifecycle and binding publication | Concurrent same predecessor; imported fork | Under lock accept one local transition/binding; preserve/report imported forks; block affected subjects, never choose by time | M0.10/M2.4 `PredecessorConflict` |
| Daemon socket/start/restart | Stale socket; two auto-start clients; keys lost; root unavailable | One live instance, private runtime/socket; reconcile sessions with root-ended events; pending if root unavailable; preserve worktrees and ordinary queues | M1.2/M1.2a `DaemonRestart` |
| Workspace creation | Crash before/after `worktree add`, before creation receipt; partial checkout edited | Reconcile exact journaled worktree against Git metadata; at most one creation; preserve edits and report partial setup; no unrelated worktree deletion | M1.4 `ForkRecovery` |
| Private observation/proposal index | Interrupted refresh; simultaneous observer/proposer | Rebuild derived index if necessary; serialize or isolate capture; fixed-base diff; never touch user index; concurrent-edit result when capture changes | M1.5/M1.6 `PrivateIndexRecovery` |
| Proposal commit object | Crash after tree/manifest/commit preparation | Reuse journaled exact tree/manifest/commit; no new timestamps/commit on same retry; no success before required refs and receipt | M1.6 `ProposalPrepared` |
| Proposal retention ref | Crash after create-only ref; collision with different commit | Preserve valid retained revision; complete journal or report pending/conflict; never overwrite conflicting ref | M1.6 `RetentionPublication` |
| Proposal branch CAS | Crash before/after CAS; external branch advanced | Compare expected/new tip, complete prepared publication if safe; if neither expected nor new, report conflict and preserve external tip | M1.6 `ProposalBranchPublication` |
| Close receipt and worktree removal | Crash before close or during cleanup; worktree path reused | Close first; repeated close returns original outcome; cleanup checks journaled identity/path, preserves proposals and unrelated/user-edited worktrees; report cleanup pending | M1.7 `CloseCleanup` |
| Notification enqueue / ack | Crash during delivery/ack; repeated observation/ack | Transactional recipient-owned queue; stable deduplication; ordinary restart retains unacked items; reindex reports delivery gap and regenerates current warnings | M2.5/M4.6 `QueueRecovery` |
| Lease creation/expiry | Ended session, restart, clock/expiry boundary, reindex | Remove stale leases consistently; never revive lease from portable history; advisory warnings only | M4.7 `LeaseRecovery` |
| Verification worktree creation | Crash or binding/checkout mismatch before command | Exact bound detached tree and clean tracked checkout required; abort before command/no attestation for initial mismatch; reconcile leftover worktree safely | M3.2 `VerificationSetupRecovery` |
| Setup/check process execution | Setup failure, exit failure, timeout, cancel, tracked mutation, child survives | Kill process group; bounded output; signed failure with explicit reason if key available; cleanup/debug retention recorded | M3.3 `EvidenceProcessFailure` |
| Attestation publication / verifier key loss | Command complete but crash before signature/receipt | Publish only fully prepared signed group; otherwise discoverable interrupted run, no fabricated pass; retries retain frozen binding | M3.3 `EvidencePublication` |
| Export file publication | Crash while writing bundle; source unavailable after export | Complete inventory/provenance/Git closure before announcing success; partial output never verifies complete; report size | M3.6 `ExportInterrupted` |
| Import staging/extraction | Malicious path/symlink/size/config; missing/tampered dependency | Validate inert staging without hooks/checks, reject unsafe input before publishing; no trust/private keys/code branches/runtime import | M3.6 `ImportStaging` |
| Import object/ref/receipt publication | Crash at each boundary; duplicate import; semantic conflict | RecordStore recovery/idempotence; preserve conflicts; no source/network prerequisite; discard only owned staging artifacts | M3.6 `ImportPublication` |
| Scorer execution / submission | Malformed, missing/extra, non-integer or out-of-range output, timeout, failure | Interrupt, choose nobody, retain exact candidate JSON/configuration; deterministic manifest-hash tie order on successful retry | M5.3 `ScorerFailure` |
| Speculation collection/evidence handoff | Restart, timeout, cancellation, never-proposed attempt | Immediate durable handoff; explicit attempt outcome; lost keys replaced through recovery; frozen candidates never retarget/re-propose | M5.1/M5.2 `RunStageRecovery` |
| Speculation resolution group / loser cleanup | Crash before/after receipt and each cleanup | One group for selection/run/winner/losers/attempts; exactly one terminal outcome; all-fail/cancel no winner; cleanup resumable after publication | M5.4 `ResolutionRecovery` |

For each publication row, inject failure immediately before and after the named boundary. Restart, retry with the original operation id, reindex in shuffled enumeration order, and compare durable results. Where relevant, lose the signer key and advance the external ref too. Passing a happy-path demo alone does not satisfy these cases.
